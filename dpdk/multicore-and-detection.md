# 多核扩展与检测数据路径

## 两种处理模型

Run-to-completion 让工作线程完成一个包的主要步骤，通常减少跨核传递。Pipeline 把阶段分开，便于组合不同能力，但引入队列、同步与缓存迁移。选型看工作量分布与端到端延迟，不靠风格偏好。

## 流归属与状态

有状态检测需要定义流键、双向映射、超时和迁移。双向流被不同核处理时，不能无设计地共享写同一状态表。可选择对称分流、软件归属转发或显式同步，每种都要记录开销。

实验应同时覆盖均匀流量和重流偏斜。平均每核负载均匀不能排除某个大流压满单核。

## 异步检测设计

转发线程提取有界特征 → 有界队列 → 检测线程/推理服务 → 返回带流标识和版本的结果 → 转发侧应用策略。

| 风险 | 必须定义的行为 |
| --- | --- |
| 队列满 | 丢特征、降采样、拒绝还是影响转发 |
| 结果迟到 | 流已结束或标识复用时如何丢弃旧结果 |
| 模型/规则更新 | 版本标记、切换点与回收 |
| 检测耗时长 | 超时、预算、隔离与降级 |
| 同一流多次结果 | 顺序、去重与策略优先级 |

上表是工程设计清单，不是某个框架的既有保证。

## 测量业务成本

分别测基础转发、流表、特征提取、检测上报、完整策略。固定输入流量和规则集，记录每阶段耗时、队列深度、丢弃和端到端延迟。异步不等于成本消失，它把成本转成资源占用、排队与策略生效延迟。
