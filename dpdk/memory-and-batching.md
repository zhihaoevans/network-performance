# DPDK 热路径：对象生命周期、批处理与缓存

## 先保证所有权正确

RX 得到的包由应用处理。TX burst 返回成功接受的数量，未接受部分仍需由应用重试或释放；不能把未发送包遗忘，也不能立即释放已经交给驱动的对象。

mbuf 可以组成多段包。长度、段链、headroom 和 offload 元数据要一致，不能假设所有包都在单块连续内存中。

## 内存池规模估算

先枚举同时持有对象的位置：RX 描述符、TX 未回收对象、各工作线程、软件 ring、应用排队以及每核 cache。将峰值占用加上余量，再用实际计数验证。池更大不等于必然更快。

| 现象 | 候选原因 | 验证 |
| --- | --- | --- |
| rx_nombuf 增长 | 池耗尽或对象长时间不归还 | 各阶段持有量、释放路径 |
| 运行一段时间才丢包 | 泄漏、积压、回收不及时 | 空闲对象趋势与 TX 返回值 |
| 增核后收益下降 | 共享池/队列竞争、跨节点访问 | 分片与本地池对比 |
| burst 增大吞吐升但 P99 变差 | 批等待或突发增大 | 同 offered load 下对比 |

计数器语义依 PMD，不能只靠一个名字下结论。

## 批处理的边界

burst 上限不应被实现为必须等满再处理。低负载时及时处理已收到的包；高负载时使用有界批量摊薄开销。比较例如 8/16/32/64 是实验矩阵，不是默认建议。

预取只在访问模式与提前距离合适时有效。复杂数据结构、随机流表和缓存容量可能让预取成本大于收益。

## 代码审查清单

- 所有错误和部分成功分支都处理了 mbuf 所有权。
- 多段包和边界长度测试覆盖。
- 每包日志、动态分配、共享写热点有明确理由。
- 队列生产/消费模式与实际线程数相符。
- 统计计数避免不必要的跨核共享写。
- 测试保留协议正确性与数据完整性检查。

参考：[Mempool](https://doc.dpdk.org/guides/prog_guide/mempool_lib.html)、[高效代码](https://doc.dpdk.org/guides/prog_guide/writing_efficient_code.html)、[Mbuf](https://doc.dpdk.org/guides/prog_guide/mbuf_lib.html)。

TX 所有权与具体返回语义还应核对当前版本的 [rte_eth_tx_burst API](https://doc.dpdk.org/api/rte__ethdev_8h.html)；返回成功接受不保证远端收到。
