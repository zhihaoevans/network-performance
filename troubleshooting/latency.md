# 尾延迟、抖动与偶发停顿

## 先审查延迟统计

确认起止事件、样本量、超时处理、开环/闭环、是否丢弃失败请求。单向测量要有时钟误差预算；P99 不应由吞吐量或平均值推算。

## 按时间窗口关联

| 伴随现象 | 候选问题 | 验证 |
| --- | --- | --- |
| 出口 backlog 增长 | 排队与突发 | 降低 offered load、观察队列 |
| CPU 节流增量 | 容器配额限制 | 实际 cgroup cpu.stat |
| 上下文切换/迁移突增 | 调度与线程竞争 | 调度事件与线程 CPU |
| 批量变大后 P99 上升 | 等待凑批 | 增加批等待上限，测低/高负载 |
| 周期性慢请求 | 定时任务、日志、回收 | 与应用阶段时间关联 |
| 重传/PTO 同时出现 | 传输恢复 | TCP/QUIC 连接指标 |
| 平均空闲但某核忙 | 队列/流偏斜 | 每核和 per-queue 统计 |

## 实验顺序

从轻载、目标负载、接近饱和三档开始。保持负载模型一致，对每档分别画或记录吞吐、失败率、P50/P99。先查明显排队和资源限制，再评估 CPU 频率、IRQ 合并和亲和性。

延迟优化可能增加 CPU 与功耗；节省 CPU 也可能增加等待。报告要写明交易条件，不把某配置称为“全场景最佳”。
