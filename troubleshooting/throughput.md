# 吞吐量不足的排查手册

## 入口信息

目标值来自链路标称、历史结果还是业务要求？帧长、流数、方向、加密、转发功能、测量层次是否一致？先排除把 bit/s、byte/s、Goodput 与线速混为一谈。

## 分支检查

| 观察 | 下一步 | 支持假设的证据 |
| --- | --- | --- |
| 发送器实际速率不足 | 查发送端 CPU、系统调用与 pacing | TX 就没达到目标 |
| 链路速率异常 | 查协商、线缆、模块与交换端口 | 两端速率/错误支持 |
| 单流低，多流高 | 看队列与 TCP 窗口 | 单核热点或在途数据受限 |
| 收包多，应用消费少 | 查 socket/业务队列与处理 | 接收积压和应用热点 |
| 小包差，大包好 | 看逐包开销与 PPS | 包速率先到平台 |
| 本地快，远端慢 | 查 RTT、PMTU、拥塞和路径 | 路径相关指标变化 |
| 随时间下降 | 查温度、内存泄漏与积压 | 资源趋势与性能相关 |

## 最小验证流程

先双向单连接，再双向多连接。两端同时采每核 CPU、接口和协议计数，保持测试持续时间和工具版本一致。一次只修改一个候选因素，回到初始配置复测。

停止条件包括错误率显著增长、影响其他业务或无法确认流量边界。最终报告需要说明瓶颈落在哪一层，以及被排除的原因。
