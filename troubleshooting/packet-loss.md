# 丢包与重传：从链路到应用

## 先定义“丢”

UDP 序号缺口、网卡 dropped、TCP 重传、应用超时是不同观测。先定义发送与接收边界，以及是否把乱序、重复和迟到计算为丢失。

## 排查表

| 层次 | 证据 | 候选原因与验证 |
| --- | --- | --- |
| 测量本身 | 抓包 dropped、客户端错误 | 降低观测负载，独立计数交叉验证 |
| 物理链路 | CRC、链路抖动、交换端口错误 | 更换已知正常链路做对照 |
| 硬件 RX | 驱动 missed/no-buffer | 看 per-queue、CPU、描述符与服务时间 |
| 软件接收 | 协议/softnet 增量 | 结合内核版本解释，查软中断热点 |
| socket | UDP 接收缓冲错误、队列积压 | 应用读取速率与批量效率 |
| 出口 | qdisc drops/backlog | 整形策略与 offered load |
| 业务 | 内部队列满、解析拒绝 | 错误类型与负载分组 |

## 反例提醒

TCP 可以因乱序或恢复机制产生重传；重传数不能直接等于物理丢包数。抓包看不到也可能是采集器丢失。不同层 dropped 可能重叠。

## 验证设计

先降低 offered load 看异常是否消失，再保持 bit/s 改包长、保持 PPS 改负载大小，辨别逐包成本和带宽限制。必要时用测试拓扑注入已知丢失，验证观察链能否识别它。

结果写成：“在条件 X 下，计数 A/B 同时变化，干预 C 使指标恢复”；没有证据时保留为候选原因。
