# LAB-003：UDP 包长、速率与损失

状态：待执行实验设计。依赖 [LAB-001](001-network-baseline.md) 双端环境。

## 假设

相同 bit/s 下较小数据报产生更高 PPS，可能更早暴露逐包处理瓶颈。假设是否成立取决于端点和路径，不能预先填写结果。

## 步骤

1. 选定不会超过已验证 PMTU 的应用长度，如 128、512、1200 byte。
2. 从低 offered load 开始，对每种长度分别递增速率。
3. 每个配置独立运行至少三次；不要把上一组历史计数算入下一组。
4. 接收端同时观察网卡、协议/socket 与应用统计。
5. 若出现持续明显损失，停止升压，缩小间隔定位转折点。
6. 再以接近相同 PPS 的方式调整 bit/s，对照逐包与字节处理成本。

## 命令形式

```bash
SERVER=198.18.0.2
iperf3 -c "$SERVER" -u -b 10M -l 128 -t 20 -J > udp-128-10m.json
```

每次改变长度或速率后使用新文件名。理论 payload PPS≈目标 bit/s ÷(应用长度×8)，这不包含链路开销，实际值以工具和计数器为准。

## 报告字段

应用长度、理论 payload PPS、实际发送/接收速率、接收丢失、乱序（若有）、jitter、各核 CPU、socket 错误与硬件错误。没有逐包时间戳时不要报告 P99。

## 恢复

停止客户端/服务端；本实验不修改系统配置。若另行调整过缓冲或队列，作为独立实验记录并恢复。
