# IPv6、隧道与 MTU 排查

## 公平比较

IPv4 与 IPv6 可能走不同路由、负载均衡和安全策略。比较前记录目的地址、实际出口、链路、CPU 和封装；同一域名解析出来的不同路径并不构成纯协议对比。

```bash
ip -6 addr show
ip -6 route show
ip -d link show
```

链路本地 IPv6 地址需要明确接口作用域。应用的双栈 socket 配置也会影响实际接受的连接类型，不能仅凭监听地址猜测流量协议。

## MTU 与隧道

外层 IP、UDP、VXLAN/Geneve 等头占用空间。内层可用大小要根据具体封装和路径计算，不能对所有隧道统一减去一个固定数。

| 现象 | 检查 |
| --- | --- |
| 小请求成功，大响应停顿 | PMTU、ICMP/ICMPv6 反馈与封装 |
| 隧道内多流仍集中 | 网卡解析/hash 使用内层还是外层 |
| 主机抓包出现大包 | 分段/聚合 offload 的观测位置 |
| IPv6 比 IPv4 慢 | 路由、策略、硬件能力是否真正一致 |
| 迁移后 MTU 问题 | 底层路径与虚拟接口配置差异 |

## 验证步骤

先测不经过隧道的底层，再测隧道内路径。固定应用长度逐级增加，记录错误、重传和实际 PMTU 线索。对比硬件隧道卸载时一次只变更相关功能，记录实际生效状态。

不要因为大包失败就盲目增大 MTU，或禁用路径发现；先确认端到端能力和错误反馈。修改虚拟接口后需要同时验证对端和中间链路，并保留恢复命令。

参考：[ipv6(7)](https://man7.org/linux/man-pages/man7/ipv6.7.html)、[Linux 分段与隧道卸载](https://docs.kernel.org/networking/segmentation-offloads.html)。
