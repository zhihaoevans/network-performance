# 抓包与计数器：不要混淆观测位置

## 最小抓包示例

```bash
IFACE=eth0
sudo tcpdump -i "$IFACE" -nn -s 128 -c 2000 -w sample.pcap 'tcp port 5201'
```

这里限制包数与快照长度以控制体积，不保证一定包含完整 TCP 选项或载荷。需要排查协议时按目标调整。-c 达不到上限时命令会继续等待，可手动停止；不能将它视作固定时长采样。

抓包文件可能包含业务信息，不直接提交仓库。关注 tcpdump 停止时报告的抓包丢弃：抓不到不等于线上没发。

## 两端对照

记录客户端与服务端地址、端口、接口、时间源及 NAT/隧道变换。用序列号、ACK、长度和时序匹配同一数据，而不是只按包号。

| 现象 | 先排除 |
| --- | --- |
| 发送端显示超大 TCP 包 | TSO/GSO 抓包位置 |
| 接收端显示合并大包 | GRO 等聚合 |
| 发送抓包显示校验和异常 | 硬件计算前的观测 |
| 单边看到重传 | 抓包丢弃、位置差异、乱序 |
| 包数不一致 | 不同层次、过滤条件、offload |

必要时在独立镜像口或硬件侧观察线上报文，再判断驱动/主机表示差异。

## 计数器证据链

同一窗口对比发送器 TX、接收网卡 RX、协议接收、应用成功处理。为每个计数注明是否包含错误、重试、聚合和过滤。计数不守恒时先检查口径，不能立即将差值视作某层丢包。

参考：[分段卸载](https://docs.kernel.org/networking/segmentation-offloads.html)、[接口统计](https://docs.kernel.org/networking/statistics.html)。命令语义以本机 tcpdump 手册为准。
