# 时间戳、时钟同步与单向延迟

## 先明确时间点

应用调用发送、进入内核、软件发送时间戳、硬件发出、硬件接收、应用读取是不同时间点。单向延迟若跨两台机器计算，还叠加两端时钟偏差与漂移。

| 方法 | 可以回答 | 主要误差 |
| --- | --- | --- |
| 应用时间戳 | 业务端到端时间 | 调度、排队、时钟同步 |
| 软件时间戳 | 内核路径附近事件时间 | 时间点与实际线上收发不重合 |
| 硬件时间戳 | 设备支持的收发事件时间 | 硬件位置、时钟域、驱动能力 |
| 同机 RTT | 往返耗时 | 包含对端处理，不能拆出真实单向值 |

## Linux 接口

SO_TIMESTAMPING 支持选择不同时间戳来源；接收时间戳可通过控制消息获得，发送时间戳使用错误队列等接口报告。应用需要解析消息类型并关联原始发送，不能把所有时间戳当成同一个时钟域。

可先查询能力：

```bash
IFACE=eth0
ethtool -T "$IFACE"
```

报告支持能力不代表硬件时间戳已经正确启用。网卡 PHC、系统时钟及 PTP 同步状态需要分别确认。

## 误差预算与验收

记录同步方式、偏移范围、漂移、时间戳分辨率、采样窗口和负载。若观察到的“收益”与时钟误差同量级，不能得出显著改善结论。

例如希望证明 2 μs 改善，却只能确认跨机偏移在几十 μs 内，实验无法支持该结论。这个数字只是误差预算示例，不是设备测量值。

测试中保存同步状态变化，不只保存开始时的一次输出。完成通知、硬件时间戳和远端应用消费是不同语义。

参考：[Linux Timestamping](https://docs.kernel.org/networking/timestamping.html)。
