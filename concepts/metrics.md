# 性能指标与分析概念

[返回概念索引](README.md)

## 速率与容量

| 概念 | 英文 / 缩写 | 含义与使用要点 |
| --- | --- | --- |
| 带宽 / 链路容量 | Bandwidth / Capacity | 在给定层次和条件下的传输能力。标称链路速率不是应用实际速率。 |
| 吞吐量 | Throughput | 单位时间实际完成的数据量或工作量。要明确发送还是接收、协议层次及是否包含重传。 |
| 有效吞吐量 | Goodput | 单位时间交付的有效业务数据量，通常排除协议开销和重复数据；应在报告中定义口径。 |
| 每秒包数 | Packets Per Second / PPS | 单位时间处理的包数。必须配合包长、方向、流数和丢包条件解释。 |
| 每秒请求数 | Requests Per Second / RPS | 应用请求处理速率；这里的 RPS 与 Linux Receive Packet Steering 不同。 |
| 每秒连接数 | Connections Per Second / CPS | 新建或完成连接的速率，需说明是否包括握手、认证和关闭。 |
| 线速 | Line Rate / Wire Speed | 接近指定链路容量的处理状态，需说明帧长、线缆开销、方向和可接受丢包。 |
| 并发量 | Concurrency | 同时处于处理或等待状态的任务数量，不等同于每秒完成量。 |

## 时间与可靠性

| 概念 | 英文 / 缩写 | 含义与使用要点 |
| --- | --- | --- |
| 延迟 | Latency | 两个明确事件之间的时间差，如发送到接收；不同测量边界不可直接比较。 |
| 往返时间 | Round-Trip Time / RTT | 发出到对应响应返回的时间，包含往返路径和相关处理时间。 |
| 尾延迟 | Tail Latency | 延迟分布高分位部分，例如 P99；反映少数慢请求的体验。 |
| 分位数 | Percentile | P99 表示按选定估计方法，约 99% 样本不超过该值；不是“最慢 1% 的平均值”。 |
| 抖动 | Jitter | 延迟的变化程度。不同工具可能使用不同定义，必须说明统计方法。 |
| 丢包率 | Packet Loss Ratio | 在明确测量边界和窗口内，未成功交付的包占发送包的比例。 |
| 重传 | Retransmission | 因超时或其他恢复机制再次发送数据。重传并不总能直接对应真实链路丢包。 |
| 超时 | Timeout | 超过预设等待期限。超时样本不能无说明地从延迟统计中剔除。 |

## 分析与优化

| 概念 | 英文 | 含义与使用要点 |
| --- | --- | --- |
| 基线 | Baseline | 固定环境、配置与负载下的参照结果。 |
| 基准测试 | Benchmark | 规定负载和测量方法的测试；结果只覆盖相应场景。 |
| 瓶颈 | Bottleneck | 当前约束整体能力的环节；优化后瓶颈可能转移。 |
| 利用率 | Utilization | 资源在指定口径下的使用程度。整体 CPU 低不能排除单核瓶颈。 |
| 饱和 | Saturation | 资源供给难以满足需求，表现可能包括排队、丢弃和等待增长。 |
| 热点 | Hotspot | 消耗较多时间或资源的代码或路径；占比高不代表一定有优化空间。 |
| 可扩展性 | Scalability | 增加资源后处理能力如何变化，要同时观察同步、通信和竞争成本。 |
| 背压 | Backpressure | 下游通过阻塞、限速或反馈约束上游，避免无界积压。 |
| 批处理 | Batching | 一次处理多个对象以摊薄固定成本；等待凑批可能增加延迟。 |
| 性能回归 | Performance Regression | 在可比条件下，新版本的目标指标变差。 |
| 观测开销 | Measurement Overhead | 采样、日志和抓包自身引入的 CPU、I/O 与时序扰动。 |

## 记录指标的最低要求

写清环境、负载、测量位置、统计窗口、样本量、重复次数及误差来源。比较 P99 时也要记录超时与失败请求；不同实验的分位数不能简单平均得到合并分位数。

TCP 吞吐量测试的方法与边界可参考 [RFC 6349](https://www.rfc-editor.org/rfc/rfc6349.html)；该文档是信息性测试框架，不是所有场景通用的验收标准。
