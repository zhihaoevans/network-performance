# 易混概念与计算示例

[返回概念索引](README.md)

## 常见区别

| 容易混淆的概念 | 区别 |
| --- | --- |
| 带宽 / 吞吐量 / Goodput | 容量、实际处理速率与有效业务数据速率；统计层次必须一致。 |
| Gbit/s / GB/s | bit 与 byte 不同，1 byte = 8 bit；网络速率通常使用十进制前缀。 |
| 高吞吐 / 低延迟 | 并非等价目标，批处理或排队可能提高吞吐却恶化延迟。 |
| 平均延迟 / P99 | 平均值可能掩盖尾部慢请求，P99 也依赖样本量和统计窗口。 |
| RTT / 单向延迟 | 路径与处理可能不对称，不能无条件用 RTT/2 替代单向测量。 |
| MTU / MSS / 帧长 | 分别涉及网络层包、TCP 数据和链路层帧；还要确认是否计入 FCS。 |
| cwnd / rwnd | 分别约束拥塞控制和接收端流量控制，不等同于 socket 缓冲区大小。 |
| RSS / RPS | 前者通常是硬件 RX 队列分流，后者是软件选择协议栈处理 CPU。 |
| TSO / GSO / GRO | 分别关注硬件 TCP 分段、通用分段和接收聚合，不能统称“减少线上包数”。 |
| 队列长度 / 服务能力 | 队列可吸收短期突发，但不自动提升持续处理能力。 |
| 零拷贝 / 零开销 | 避免某次复制不意味着没有管理、同步与硬件传输成本。 |
| Lock-free / Wait-free | 前者保证系统整体进展，后者要求每个操作在有界步骤内完成。 |

## 示例一：速率单位

理论换算：

- 10 Gbit/s ÷ 8 = 1.25 GB/s。
- 这是单位换算，不是应用可达到 1.25 GB/s 的保证。
- 协议头、链路开销、重传和应用处理会改变有效吞吐量。

## 示例二：同样链路速率，小包要求更高 PPS

计算式：PPS = 链路 bit/s ÷ 每帧占用的 bit 数。

以普通以太网、10 Gbit/s、64 byte 帧（含 FCS）为假设，另计 8 byte 前导码/SFD 与 12 byte 帧间隔对应的链路时间：

10,000,000,000 ÷ ((64 + 8 + 12) × 8) ≈ 14.88 Mpps。

这是给定假设下的理论估算，不是本仓库实测值。若工具不计 FCS，或存在封装、不同帧格式，需重新核对口径；帧间隔占用时间，不是帧内字节。

## 示例三：BDP

假设目标带宽为 1 Gbit/s，RTT 为 20 ms：

BDP = 1,000,000,000 × 0.020 ÷ 8 = 2,500,000 byte，约 2.5 MB。

这是在途数据规模的参考量，不表示把某个 socket 缓冲区设为 2.5 MB 就能达到线速；还受 cwnd、rwnd、丢包与端系统能力约束。

## 示例四：优化收益

假设吞吐量从 8 提升到 10 Gbit/s：

相对提升 = (10 - 8) ÷ 8 × 100% = 25%。

假设 P99 从 200 降至 150 μs：

相对下降 = (200 - 150) ÷ 200 × 100% = 25%。

这些是演算数字，不是测试结果。正式报告要同时给出绝对值、基线、负载、重复次数与波动，不能仅报告百分比。
