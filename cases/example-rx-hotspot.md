# 演示案例：总 CPU 不高，吞吐却受限

类型：假设情景，用于展示排查逻辑。没有实测数值，不表示某台机器已经出现或解决该问题。

## 现象

假设多核主机整体 CPU 看起来不高，单连接吞吐停止增长。不能因此排除 CPU 限制。

## 排查链

| 步骤 | 假设 | 需要取得的证据 | 解释边界 |
| --- | --- | --- | --- |
| 1 | 测试发送器受限 | 实际 TX 与发送线程 CPU | 先排除输入不足 |
| 2 | 单核处理上限 | 每核/每线程利用率 | 总 CPU 会稀释热点 |
| 3 | 单流集中一个 RX 队列 | per-queue 计数和 RSS 配置 | 不代表 RSS 失效 |
| 4 | 传输窗口受限 | ss 的连接状态 | 可能与单核限制同时存在 |
| 5 | 多流能分散工作 | 同总负载多流对比 | 多流还可能改变窗口总量 |

## 后续行动

若证据支持单流热点，继续分析热点路径或业务分流；若支持窗口/RTT 约束，则走 TCP 排查。不要仅因多流快就立即增加队列或开启 RPS。

## 验收要求

只有取得真实数据、干预对比与恢复结果后，才能写成真实案例。结论应注明是否改善了单流、总吞吐或仅改变了工作负载。
