# 应用网络 I/O：批量、事件循环与背压

## 先量清应用热路径

将请求时间拆成排队、读取、解析、业务、序列化、写入和等待下游。把系统调用次数、每次字节数、锁等待和分配次数与吞吐关联。网络栈快并不能修复慢数据库或串行锁。

## 常见选择

| 机制 | 可能收益 | 正确性与性能边界 |
| --- | --- | --- |
| epoll | 管理大量就绪事件 | 仍需处理短读/短写、关闭与错误 |
| ET 模式 | 减少重复就绪通知 | 非阻塞并读/写到 EAGAIN，避免饿死其他连接 |
| 有界批处理 | 摊薄系统调用和队列成本 | 限制批大小/等待时间 |
| 连接复用 | 减少握手和初始化 | 空闲生命周期、失效重建 |
| MSG_ZEROCOPY | 避免部分大块数据复制 | 完成通知前不得复用相关缓冲 |
| io_uring | 提交/完成模型与批量机会 | 依内核/操作支持，需要独立基准 |

## 背压是接口契约

每条队列定义最大长度、满时行为、超时、取消和优先级。发送慢时不能无限追加输出缓冲；否则测到高接收吞吐，却把内存和尾延迟问题推迟到以后。

## 优化顺序

先减少每包不必要工作，再试批量，再评估数据复制与执行模型。保留协议解析边界检查，避免以删除校验换“性能提升”。零拷贝、小包、缓存命中和网络条件会交互，不预设一定获益。
