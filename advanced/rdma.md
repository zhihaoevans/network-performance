# RDMA/RoCE：性能分析入口

范围：基础模型与实验设计，不提供交换机厂商配置配方，也未收录 RDMA 实测。

## 基本对象

| 术语 | 作用 |
| --- | --- |
| MR / Memory Region | 注册可访问的内存范围与权限，使用相关 key |
| PD / Protection Domain | 组织与隔离相关 RDMA 资源 |
| QP / Queue Pair | 提交发送/接收工作所用的队列对 |
| CQ / Completion Queue | 获取完成记录，检查状态与资源回收 |
| Send/Receive | 通过消息语义交互，需要相应接收资源 |
| RDMA Read/Write | 在授权范围访问远端内存的操作 |

完成状态与远端业务处理完成不是同一概念；具体顺序和可见性按传输/操作语义处理。RoCE 使用以太网承载，网络拥塞与流量管理仍需要端到端设计。

## 优化前先测量

| 维度 | 对照组 |
| --- | --- |
| 消息大小 | 小消息延迟、大消息带宽 |
| 并发深度 | 单 outstanding 与多 outstanding |
| 内存注册 | 预注册复用与频繁注册 |
| 完成处理 | 轮询/通知及批量回收 |
| 放置 | NIC、线程、内存 NUMA 位置 |
| 网络负载 | 空闲、背景竞争、拥塞与故障恢复 |

记录操作类型、传输类型、设备/固件、库版本、队列深度和实际错误。不能把一个 ib_write_bw 数值直接作为应用数据库或 GPU 通信收益。

## 拥塞与网络运维

PFC、ECN、拥塞控制算法和交换机缓冲的效果依设备、优先级和拓扑组合。避免只打开一个功能就声称“无损网络”。需要观察队列、暂停、拥塞标记、重试、应用超时和竞争流影响。

注册内存与资源生命周期错误也会表现为停顿或失败。先确认正确性、完成状态和接收资源供给，再归因网络瓶颈。

参考：[NVIDIA RDMA Programming Manual v1.7](https://docs.nvidia.com/rdma-aware-networks-programming-user-manual-1-7.pdf)。这是基础 API 资料，不表示其具体版本适配所有当前设备。
